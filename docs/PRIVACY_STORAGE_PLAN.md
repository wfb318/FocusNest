## 1. 用户已确认的要求

1. FocusNest 应根据内容的私密程度采用不同的保存方式，由平台做好自身的隐私保护。
2. 日记默认保存到用户自行选择的真实本地文件夹；支持导入已有日记，也支持绑定目录直接编辑。
3. 不同账号分别管理本地目录绑定，切换账号时不能自动沿用或展示上一个账号的日记。
4. 对需要保密的内容，提供两条保存途径：服务器端加密保存，或仅保存到本地文件夹。
5. 普通任务、日程、计时等数据可以继续使用服务器，不要求本轮全部迁移到本地或全部加密。
6. 用户自己的磁盘加密、电脑访问控制、第三方同步工具等个人保密工作不纳入本轮开发；平台仍须避免越权、意外上传、错误覆盖等由自身造成的风险。
7. 2026-11-04 先整理要求与分步计划；2026-11-05 用户授权实施第一步。仅推进当次指定范围，不自动执行后续步骤。

## 2. 存储方式与隐私等级

这里的等级描述平台如何处理数据，并不代表本地文件天然具备加密能力，也不构成绝对安全承诺。

| 方式 | 适用内容与默认值 | 平台保存什么 | 平台的保护责任 |
| --- | --- | --- | --- |
| 普通云端保存 | 普通任务、日程、计时，以及当前普通笔记等 | 按现有业务保存必要数据 | 账号鉴权、数据归属校验、HTTPS、日志脱敏、受控备份 |
| 云端加密保存 | 用户主动选择保护的受支持内容 | 受保护字段的密文，以及列明的必要元数据 | 平台管理密钥、按权限解密；不在其他表、索引、预览或日志中留下同一内容的明文副本 |
| 仅本地文件夹保存 | 日记默认采用；其他内容后续逐步支持 | 服务器不保存该内容；目录授权与绑定保存在当前浏览器 | 只访问用户授权的目录；不上传正文、标题、文件名、附件、内容索引或本地目录信息 |

两个需要向用户说清楚的边界：

- 云端加密是服务器端加密，不是端到端加密。后端处理请求时仍可解密，有相应权限的运营人员仍可能读取。不能宣传为“平台也看不到”。
- 仅本地保存是存储位置承诺，不要求用户设置额外解锁密码，也不在本轮增加本地文件加密或恢复密钥体系。

本轮规划先落地日记本地化，再建立云端加密能力，之后逐步让笔记等内容接入。具体开放的内容类型必须在每一步交付中列明，不做一个按钮声称所有模块都已支持。

## 4. 本地日记的行为要求

### 4.1 绑定目录与导入

- **绑定目录**：用户选择目录并授权，FocusNest 直接编辑其中的文件，不把它复制到服务器。用户换设备或更换网站域名后，需要在该环境重新绑定。
- **导入日记**：用户选择文件，将副本写入当前账号已绑定的日记目录。原文件保持不变；未绑定目录时先引导绑定，不能自动上传替代。
- 首批格式建议限定为 UTF-8 Markdown（`.md`）；其他格式后续单独评估，避免首步引入复杂解析。
- 建议新建文件使用 `YYYY/MM/YYYY-MM-DD.md`；该目录结构是待实现的默认方案，不表示现有磁盘中已经存在。
- 保留现有“一天一篇日记”的基本体验。导入时遇到同一天多文件、无有效日期、无法解码等情况，给出待处理清单，不能静默覆盖或跳过。
- 在实施导入前定稿日期、标题、时区和元信息的 Markdown 格式；优先保证普通 Markdown 编辑器可以阅读，不依赖私有二进制格式。

### 4.2 文件操作的可靠性

- 打开文件前检查目录授权；权限失效、目录移动或磁盘不可用时明确提示，不转而保存到服务器。
- 保存完成前不能提示“已保存”。写入失败时保留当前编辑内容供用户重试或手动导出。
- 记录读取时的内容版本或指纹，写入前检查外部编辑和多标签页修改，发生冲突时展示选择或保存副本。
- 用户主动刷新或重新进入页面时识别外部修改；第一版不承诺所有浏览器均能实时监听目录。
- 不扫描授权目录之外的磁盘；导入路径和附件引用不能绕过授权目录边界。
- 日记渲染不得执行脚本；本地模式不自动加载正文中的远程图片或其他外部资源，避免通过渲染向第三方泄露阅读行为。
- Markdown 中的日记图片、附件若支持，应保存在本地并使用受控的相对引用；第一版若尚未支持，明确显示限制，不能沿用云端附件上传入口。

### 4.3 账号与目录归属

- 绑定按“当前站点环境 + 当前设备浏览器 + 稳定用户 ID”隔离；不按可修改的昵称识别用户。
- 浏览器可保存目录句柄以便下次访问，但每次使用仍检查权限；服务器不接收本地绝对路径或目录句柄。
- 当前账号没有绑定时，显示未绑定状态；不能回退到公共目录或前一个账号的目录。
- 登出、会话失效、切换账号时，清理页面内容、编辑草稿、内存索引、对象 URL 和活动目录引用。已经开始的异步操作不能把旧账号结果写回新账号页面。
- 由用户主动选中同一个真实目录不等于平台能建立操作系统级隔离；本轮不开发文件系统权限管理。
- 解绑只解除应用绑定，不删除磁盘文件。真正删除日记文件应为独立、明确的用户操作。

## 5. 云端加密的行为要求

- 用户登录仍使用现有密码哈希与会话机制；内容加密不得复用密码哈希或 JWT 签名密钥。
- 采用维护中的加密库与带完整性校验的标准方案；建议评估 AES-GCM，不自行发明加密算法。具体库和密文格式在对应开发步骤定稿。
- 独立管理数据加密密钥；密钥不进入代码仓库、响应、日志或同一份数据库备份。正式部署优先使用独立密钥管理服务或受限的密钥文件挂载。
- 密文包含算法/格式版本、密钥标识、随机参数及认证信息；同一密钥下不得重复使用 GCM nonce。将用户归属、对象 ID、字段等上下文纳入校验，防止密文被替换到其他对象后误用。
- 先校验用户是否有权访问，再解密；权限校验不能因为内容已经加密而省略。
- 缺密钥、认证失败或密文被篡改时停止操作，不回退写入明文，也不向用户暴露内部密钥信息。
- 保护范围至少列明标题、正文和附件；文件名、标签、文件夹名、关联关系等是否受保护须逐项列清，不能只加密正文就笼统称为全部加密。
- 若为受保护文档提供预览，提取文本、预览 JSON、缩略图、临时文件和缓存也要纳入保护，不留下新的长期明文副本。
- 普通云端与加密云端的存储标识必须区分；首版不承诺所有查询功能原样可用。正文搜索、标题排序、分页等要在开发前给出明确策略，不能保留明文副本来维持搜索。
- 平台负责密钥备份、恢复和轮换。用户不需要承担平台密钥的保管责任；平台不能把密钥丢失后的恢复问题转嫁为“忘记用户密码”。

### 第一步：确定存储契约与模式入口

**验收**：可识别当前来源；本地未绑定时不发出云端日记读写请求；现有云端实现仍可供显式的历史迁移使用；不提前宣称隐私改造已完成。

- 确定哪些字段加密、哪些必要元数据仍可见；验证密文长度对现有字段和文档容量限制的影响。
- 为接入对象准备明确的加密标识/密文字段迁移方案，不直接拿密文替换现有 JSON 预览或字符串后假设旧代码可用。
- 不改登录密码哈希，不复用 JWT 密钥；无配置时加密写入必须失败关闭。

**预计涉及**：建议新增 `backend/app/core/content_crypto.py`；修改 `backend/app/core/config.py`，按需要增加依赖与测试。数据库迁移编号在实施时根据实际最新版本分配。

**验收**：加解密往返、密文篡改、错误密钥、错误对象归属、密钥缺失、旧密钥轮换和备份恢复均有有效测试；源码、日志、响应及普通 DB 备份无明文密钥。

### 第六步：业务模块接入保存方式选择

首批已实现笔记普通云端和云端加密的新建、查看、编辑、删除及独立切换。密文标题和正文从详情读取，关键词查询只覆盖普通云端。本机已完成数据库迁移及开发密钥配置。 [第六步修改与验证](PRIVACY_STORAGE_STEP6.md)

收尾已接入日记可选云端加密和文档原件、预览加密，并完成笔记本地目录评估。日记两处存储可逐篇复制，文档通过独立入口切换。真实目录复制留待实机复验。 [第六步收尾修改与验证](PRIVACY_STORAGE_STEP6_COMPLETION.md)

**目标**：让用户能够真正选择，而不是只有一个无效的设置开关。

- 优先让笔记接入云端加密；普通笔记的行为保持清楚。是否进一步支持笔记真实本地目录，在该步骤列为独立交付项，不把现有逻辑文件夹伪装成磁盘目录。
- 日记若开放云端加密作为可选方式，仍默认本地；只有用户主动选择并看到上传范围后才执行同步。
- 文档随后接入时，同时处理原始文件、预览与下载；本地文档不得沿用服务器上传解析流程。
- 定稿首版搜索/排序限制与解密预览流程；页面直接显示“普通云端 / 云端加密 / 仅本地”，不使用含糊的“绝对私密”。
- 切换来源采用显式迁移：先写目标并验证，再按用户选择处理来源副本，失败保留原件；不因配置开关改变就自动删除或上传。

**预计涉及**：对应笔记、文档、日记的前端 API/类型/页面与后端 models、schemas、services、repositories；必要的 Alembic 迁移及本地存储适配器。

**验收**：每个对外显示支持的模块都有完整的创建、读取、编辑、删除及切换用例；跨账号拒绝访问；云端加密对象没有同内容明文影子字段；本地对象不发上传请求。

### 第七步：历史云端内容加密与副本清理

已接入按选定记录分批迁移、事务回执、在线明文清理和隔离恢复检查，并用合成备份演练独立密钥恢复与旧副本拦截。正式备份保留期限和真实旧副本处置待部署时执行。 [第七步操作与验证](PRIVACY_STORAGE_STEP7.md)

**目标**：让旧数据获得与新数据一致的保护，而不只加密新写入内容。

- 提供可中断续跑的历史数据迁移，先识别普通与受保护对象，再分批加密；不能把所有普通内容未经选择就迁移。
- 校验解密结果后清理被替代的在线明文字段、预览或索引，记录不含内容的迁移结果。
- 平台统一管理备份保留、过期清理和恢复验证；运维回滚不能把用户已经选择本地保存的内容自动恢复上线。
- 密钥备份与数据备份分离，覆盖恢复演练；历史明文备份尚未过期时，不宣布历史明文已全部消除。

**数据库/API**：可能需要数据迁移脚本及管理命令；不通过普通用户 API 暴露其他账号数据或密钥。

**验收**：混合新旧格式可控、重复迁移幂等、失败可定位；恢复演练通过；明确仍存在的旧副本及到期处理方式。

### 第八步：平台隐私验收与正式部署收尾

已完成本地验收，覆盖隔离 Chrome 的请求、原生 OPFS 读写及双标签页账号隔离，并完善错误日志和发布检查。系统选择器授权及正式环境须按发布检查补验。 [第八步验收结果](PRIVACY_STORAGE_STEP8.md)

**目标**：确认整条数据流符合承诺，而不只是单个页面看起来正常。

- 网络与日志检查：本地日记正文、标题、文件名、附件、路径和索引均不出站；包含 Markdown 外部资源和错误场景。
- 账号检查：退出、失效、切换、多标签页、迟到请求和迁移流程均不串号。
- 文件检查：拒绝授权、写盘失败、外部修改、目录移动、导入冲突均不丢内容或静默覆盖。
- 加密检查：越权、篡改、缺密钥、轮换、恢复、文件预览与备份流程均覆盖实际支持的模块。
- 部署检查：HTTPS、正式域名、Cookie、服务权限、数据库内网访问、密钥独立保管和内容不进日志；浏览器兼容性在发布时重新核对。
- 更新用户说明与实际代码清单，明确已支持项、限制、未处理历史副本；未完成的条目继续列为待办。

**验收**：相关后端测试、前端测试、类型检查和构建通过，并有真实浏览器目录读写与网络检查证据；不将“只写了测试”当作浏览器授权行为已验证。

## 7. 浏览器约束与降级原则

网页绑定真实文件夹依赖浏览器支持，不能假定所有桌面和移动浏览器都能使用。目录选择 API 需要安全上下文和用户操作；开发环境需按浏览器规则验证，正式站点使用 HTTPS。权限需要按实际状态检查，不能承诺永远有效。[MDN 目录选择说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)、[MDN 目录权限说明](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemHandle/requestPermission)。

实施建议：第一版优先验证支持目录 API 的桌面 Chrome/Edge；其他浏览器显示限制并提供手动文件导入/导出。手动下载不等于已经持续保存到绑定目录。桌面客户端、浏览器扩展和自建本地同步服务不在本轮必做范围。

## 8. 不纳入本轮的事项

- 用户电脑、磁盘、系统账户的保密管理；用户自行使用的第三方同步工具。
- 本地加密文件库、额外解锁密码、用户恢复密钥体系。
- 端到端加密与“运营者也无法读取”的承诺。
- 全模块一次性本地化、所有浏览器完整支持、跨设备自动同步本地目录。
- AI 开发、自动读取私密目录，以及 Phase 8 Statistics 的功能开发。

排除以上工作，不免除平台对授权目录边界、账号隔离、内容不出站、文件操作可靠性、云端权限和平台密钥管理的责任。
